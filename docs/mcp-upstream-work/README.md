## 更新规则

- 每次开始工作先读本页；处理具体功能时再读对应能力、决策和验证记录。
- 每完成一个可独立说明的工作单元、得到测试结果、调整方案或遇到阻碍，就更新对应文档。结束一段工作时补工作日志和下一步。
- 本页负责当前任务状态；PLAN 负责范围与约束；CAPABILITIES 负责逐项实现；VALIDATION 负责执行证据，避免在多处维护互相冲突的进度副本。
- 代码变更的相关进度和证据随该次提交保存。提交是恢复检查点，不代表平台已经验收；测试结果必须对应明确提交和环境。
- “已实现”“编译通过”“运行通过”“待社区补测”分别记录。功能尚未实现不能归入缺设备；测试失败需保留结果并跟进修复。
- 关键方案先记录状态和理由，验证后再确定；后续变更保留旧决策及替代关系，避免重复走已否定的路线。
- 本目录不保存访问凭据、私钥、个人测试数据或大体积原始日志；记录脱敏结果、构建链接和证据位置。
- 最终保留用户文档、必要开发说明、测试代码和 PR 验证摘要；过程记录按 CLOSEOUT 归档并移除。
